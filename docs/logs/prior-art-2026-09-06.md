## 2. Detail on CONFIRMED / PARTIAL items

**H1 — MCP tool annotations.** Classifies on: server-author-declared hints per tool, not derived from anything mechanical by MCP itself. Advisory/untrusted by spec text. License: MCP spec is open (Apache-2.0 per modelcontextprotocol.io repo, not independently re-verified this pass). rwxmap could absorb: the four field names and their exact semantics/defaults as an **output vocabulary** — rwxmap's r/w/x could map onto `readOnlyHint`/`destructiveHint`/`idempotentHint` so its output is drop-in usable as MCP tool annotations.

**H2 — Google AIP.** Classifies on: declared method type (standard verb enum) plus HTTP method mapping, chosen at design time by the API author, not inferred. Apache-2.0-style open license (aip.dev is CC-BY-SA per site footer, not independently re-verified this pass). rwxmap could absorb: the custom-method `:verb` suffix convention as a strong positive signal for the verb-library lookup (a path segment matching `:verb` is a high-confidence operationId-equivalent).

**H3 — RFC 9110.** Classifies on: HTTP method alone, normatively. This is exactly rwxmap's method-signal half. Public-domain-equivalent (IETF Trust Legal Provisions). rwxmap could absorb: the exact safe/idempotent method lists as the fixed lookup table for its HTTP-method signal (GET/HEAD/OPTIONS/TRACE=safe; +PUT/DELETE=idempotent; POST=neither).

**H4 — Zalando guidelines.** Classifies on: none mechanically — these are prose authoring rules ("don't put verbs in paths"), enforced by a linter (Zally) matching against them. License: Zalando guidelines are CC-BY 4.0 (not independently re-verified this pass); Zally is MIT (not independently re-verified this pass). rwxmap could absorb: the rule text itself as documentation/justification for why operationId-verb lookup is a *necessary* fallback (well-designed APIs deliberately omit verbs from paths), reinforcing that method-only classification is insufficient.

**H5 — openapi-mcp (wrxck).** Classifies on: HTTP method only (no verb-library lookup). Mechanical (rule table), not LLM. MIT license. rwxmap could absorb: the exact method→hint mapping table as a cross-check/second source for its own method-signal table, and the observation that no found tool adds a verb-library signal — this is rwxmap's differentiator, not something to absorb from elsewhere.

**H6 — APIs.guru.** Classifies on: n/a, it's a corpus not a classifier. CC0-1.0. rwxmap could absorb: the entire directory as the training/lookup corpus for its verb library (operationId and path segments across many real specs), fetchable via the documented REST API or git clone (with the caveat the README itself discourages raw git/RSS use in favor of the REST API for structural stability).
